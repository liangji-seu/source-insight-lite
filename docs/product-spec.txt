我要开发一个用于阅读大型系统源码的 VS Code 插件。

这个工具不是普通的代码编辑器，而是一个：

**Large Codebase Architecture Explorer / Source Insight for Modern Systems**

主要目标是帮助我理解：

- vLLM
- SGLang
- PyTorch
- CUDA 项目
- C/C++ 系统项目
- 最终包括 Linux Kernel

这类大型源码。

---

# 一、产品目标

传统 VS Code 更擅长：

- 文件浏览
- 搜索
- Ctrl+Click 跳转定义
- Find References
- Outline
- Git

但是阅读大型系统源码时，我真正缺少的是：

> “这个系统在架构上到底是怎么组织的？”

我希望这个插件能够提供一种：

**Architecture Navigation**

而不仅仅是：

**Symbol Navigation**

传统阅读方式：

文件
→ 类
→ 函数
→ 定义

我希望实现：

系统
→ 子系统
→ 模块
→ 类
→ 接口
→ 调用链
→ 源码

例如：

vLLM
→ Engine
→ Scheduler
→ KV Cache
→ KVCacheManager
→ allocate_slots()
→ 源代码

---

# 二、第一阶段范围

第一版不要试图直接支持 Linux Kernel。

MVP 优先支持：

- Python
- vLLM
- SGLang

主要验证大型 Python 系统的架构分析能力。

后续再扩展：

- C++
- CUDA
- clangd
- Linux Kernel

1. Workspace 索引
2. Module 分析

5. Method 分析
6. Inheritance Graph
7. Module Dependency Graph
8. Call Graph
9. Callers / Callees
10. Architecture Explorer
11. AI Explain Module
12. AI Explain Class
13. VS Code 源码跳转

# 三、总体架构原则

整个系统必须拆成两层：

## Layer 1：VS Code Extension

使用：

- TypeScript
- VS Code Extension API

负责：

- UI
- Sidebar
- TreeView
- Webview
- 命令
- 当前编辑器上下文
- 点击源码跳转
- 与分析后端通信

---

## Layer 2：Code Analysis Engine

第一版推荐 Python。

负责：

- 扫描源码
- AST Parsing
- Symbol Extraction
- Dependency Analysis
- Call Graph
- Inheritance
- Architecture Model
- 数据持久化

两层之间不要强耦合。

推荐：

VS Code Extension
    ↓
HTTP / JSON-RPC / stdio
    ↓
Code Analysis Engine
    ↓
AST / Tree-sitter / LSP
    ↓
Graph / Database

未来即使我重新做独立 Desktop App，也可以复用 Analysis Engine。

kv_cache_manager

# 十、Module Dependency Graph

分析：

import
from ... import ...

以及类之间的成员依赖。

例如：

Scheduler
    ↓
KVCacheManager
    ↓
BlockPool

支持区分关系类型：

- import
- inheritance
- owns/member
- calls

重要：

大型项目不能默认把所有边全部显示，否则图会完全不可读。

必须提供 Filter：

[✓] inheritance
[✓] member dependency
[ ] import
[ ] function calls

# 十一、Call Graph

    ↓

   /        
  ↓          ↓

SchedulerOutput

支持两个方向：

Callees

当前函数调用了谁。

Callers

谁调用了当前函数。

需要明确标记：

Resolved

Unresolved

Dynamic

不要伪造确定性。

# 二十六、准确性原则

静态代码分析一定存在不确定性。

尤其 Python 有：

- dynamic dispatch
- monkey patch
- decorators
- getattr
- runtime import

因此每个关系可以增加：

confidence

例如：

HIGH
MEDIUM
LOW

或者：

STATIC
INFERRED
UNRESOLVED

不要向用户展示错误的“绝对确定关系”。
